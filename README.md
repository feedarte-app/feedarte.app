# FeedCraft — динамічні креативи для каталогів Meta та TikTok

FeedCraft бере XML-фід товарів, накладає на кожен товар ваш дизайн (ціна, знижка, бренд, бейджі, логотипи) і віддає новий фід з власними картинками. Цей фід підключається до Meta Commerce Manager або TikTok Catalog. Дані оновлюються автоматично за розкладом, за замовчуванням щогодини.

```
Проєкт → Фід (XML-джерело) → Дизайни (1:1, 4:5, 9:16, 1.91:1 …) → Вихідний фід + картинки
```

## Можливості

- **Імпорт фідів.** Підтримуються Google Merchant / Meta RSS (`g:` поля), Atom і YML (Rozetka, Prom). Розбір потоковий, тож великі каталоги не перевантажують пам’ять: 20 000 позицій (17 МБ) обробляються за ~2 с. Поля визначаються автоматично.
- **Розклад.** Кожен фід оновлюється за своїм інтервалом (15 хв … 1 доба). Перемальовуються лише товари, у яких щось змінилось. Видалені з джерела товари зникають і з вихідного фіду.
- **Конструктор.** Шари, текст зі змінними `{{title}}`, фото товару з будь-якого поля, завантажені логотипи, фігури (зокрема кут-трикутник і бейдж-вибух), ~2100 іконок, тіні, градієнти. Є прилипання до направляючих, undo/redo, гарячі клавіші і перегляд кожного товару з фіду.
- **Логіка знижок і умов.** Обчислювані поля: `current_price_fmt`, `old_price_fmt`, `discount_percent`, `discount_amount_fmt`, `has_discount`. Кожному шару можна задати умову «Показати/Приховати, якщо …» (існує, дорівнює, містить, більше/менше …). Шар автоматично ховається, якщо всі його поля порожні: у товарів без знижки бейдж «-30%» і закреслена ціна просто зникають.
- **Однаковий рендер.** Редактор і сервер малюють однаковим кодом і однаковими шрифтами (19 сімейств із кирилицею), розбіжність менше 0,5% пікселів. Кнопка «Перевірити» показує серверний результат для поточного товару.
- **Варіації.** Якщо в кількох варіантів (розміри, кольори) підсумкова картинка однакова, вона рендериться один раз (контент-хеш). У тесті на 20 000 позицій вийшло 1 535 унікальних картинок, повний прогін зайняв ~35 с.
- **Кілька дизайнів на фід** для A/B-тестів. Кожен має власний URL вихідного фіду, фільтр товарів (напр. лише зі знижкою) і кнопку «Дублювати».
- **9 готових шаблонів** під 4 формати. Будь-який дизайн можна зберегти як власний шаблон.
- **Користувачі.** Реєстрація (відкрита / з підтвердженням / закрита), ролі admin/user, кожен бачить лише свої проєкти.
- **Адмін-панель.** Користувачі, стан воркерів і черги, фіди з помилками, невдалі задачі з кнопкою «Повторити», вільне місце на диску.

## Архітектура

| Компонент | Технології |
|---|---|
| API + веб | Node 22, Fastify, React + Vite + Tailwind |
| БД | PostgreSQL 16 (Drizzle ORM, міграції запускаються автоматично) |
| Черга задач | Власна черга на Postgres (`FOR UPDATE SKIP LOCKED`): ретраї, дедуплікація, відновлення «завислих» задач. Redis не потрібен |
| Рендер | `@napi-rs/canvas` (Skia), пул потоків на всі ядра CPU |
| Файли | Локальний диск (`/app/data`), картинки з контент-хешем у назві віддаються з кешем `immutable` |
| HTTPS | Caddy: автоматичні сертифікати Let’s Encrypt |
| Бекапи | Щоденний `pg_dump` + завантажені логотипи, зберігаються 14 днів |

Процеси: `app` (API + інтерфейс) і `worker` (розклад, синхронізація, рендер). Воркерів можна масштабувати: `docker compose up -d --scale worker=2`.

## Деплой (рекомендовано: Hetzner Cloud + Docker)

1. Створіть сервер **Ubuntu 24.04**: Hetzner CX33 (4 vCPU / 8 GB) або більший. Увімкніть Backups у панелі Hetzner.
2. Направте домен (A-запис) на IP сервера, напр. `feeds.ludi.digital`.
3. На сервері:
   ```bash
   bash deploy/setup-ubuntu.sh          # Docker, firewall, автооновлення безпеки, swap
   git clone <repo> /opt/feedcraft && cd /opt/feedcraft
   cp .env.example .env && nano .env    # DOMAIN, PUBLIC_URL, паролі
   docker compose up -d --build
   ```
4. Відкрийте `https://ваш-домен`. Адмін-акаунт створюється з `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

Оновлення коду: `./deploy/update.sh`. Відновлення БД: `./deploy/restore.sh backups/db-….dump`.
Моніторинг: додайте `https://ваш-домен/api/health` в UptimeRobot або Better Stack (безкоштовно). Ендпоінт повертає стан БД і кількість живих воркерів.

## Автодеплой через GitHub (основний спосіб)

Кожен `push` у гілку `main` автоматично проходить такі кроки:
1. GitHub перевіряє типи й збирає проєкт. Якщо збірка падає, деплою не буде.
2. Код завантажується на сервер (`/opt/feedcraft/releases/<commit>`).
3. Робиться **бекап БД перед оновленням** (`/opt/feedcraft/backups/predeploy-*.dump`, зберігаються останні 10).
4. Збирається новий Docker-образ, сервіси перезапускаються.
5. Health-check. Якщо нова версія не піднялась, відбувається **автоматичний відкат** на попередню.

Дані (БД, картинки, завантажені логотипи) лежать у Docker-томах, деплой їх не чіпає. Міграції БД лише додають нове.

Налаштування: секрет `SSH_PRIVATE_KEY` у GitHub (Settings → Secrets and variables → Actions), а `SERVER_IP` і `DOMAIN` — у `deploy/config.env`. Під час першого деплою сервер налаштовується автоматично (Docker, firewall, swap, оновлення безпеки), пароль БД генерується прямо на сервері. Перший зареєстрований користувач стає адміністратором.

## Підключення до реклами

- **Meta:** Commerce Manager → Каталог → Джерела даних → Заплановане оновлення фіду → вставте URL вихідного фіду (картка дизайну → «Копіювати»), розклад «Щогодини».
- **TikTok:** Catalog Manager → Add products → Data feed → той самий URL.

Вихідний фід має формат Google/Meta RSS 2.0. `image_link` замінено на згенеровану картинку, оригінальні фото лишаються в `additional_image_link`. Назви картинок містять хеш вмісту, тож коли змінюється ціна чи дизайн, змінюється й URL, і Meta/TikTok одразу підтягують нове зображення.

## Локальна розробка

```bash
npm install
# Postgres: DATABASE_URL=postgres://feed:feed@localhost:5432/feedcraft
npx tsx scripts/sample-feed.ts 600 --serve       # тестовий фід на :4000
ALLOW_PRIVATE_URLS=true npm run dev:api           # :3000
ALLOW_PRIVATE_URLS=true npm run dev:worker
npm run dev:web                                   # :5173
```

Корисне: `npm run typecheck`, `npm run build`, `npx tsx scripts/template-sheet.ts <dir>` (усі шаблони одним аркушем).

## Змінні середовища

| Змінна | Опис |
|---|---|
| `DOMAIN`, `PUBLIC_URL` | Домен і публічна адреса (у посиланнях на картинки та фіди) |
| `POSTGRES_PASSWORD` | Пароль БД |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Перший адміністратор |
| `WORKER_CONCURRENCY` | Скільки задач одночасно виконує один воркер (2) |
| `RENDER_THREADS` | Потоки рендеру (за замовч. кількість ядер − 1) |
| `MAX_FEED_MB` | Максимальний розмір фіду-джерела (300) |
| `BACKUP_KEEP_DAYS` | Скільки днів зберігати бекапи (14) |
| `ALLOW_PRIVATE_URLS` | Лише для розробки: дозволяє фіди з localhost |

## Безпека

- Паролі зберігаються як bcrypt-хеші.
- Сесії живуть у httpOnly-cookie (SameSite=Lax, Secure).
- POST-запити з чужих доменів відхиляються (захист від CSRF).
- На вхід і реєстрацію діє rate-limit.
- Проєкти ізольовані між користувачами.
- Захист від SSRF: фіди й картинки не можна завантажити з внутрішніх адрес, localhost чи метаданих хмари.
- Ліміти на розмір фідів і картинок.
- SVG-файли віддаються з CSP, який блокує скрипти.
- Firewall відкриває лише порти 22, 80 і 443.
